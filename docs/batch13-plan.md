# 批次 13 计划：目录与容量的边界

日期：2026-10-06
评估基线：`5da427b7`（上游 `main`，阶段一至四与功能复查修复已完成）
依据：`docs/minios-roadmap.md` §6「文件系统」子项一（扩展容量与目录能力），以及 `README.md` §后续规划同一条目——其验收要点明确写了「**不能只调大 `FSSIZE`**」。

**本批次只做「把边界变成事实」，不改磁盘格式、不改既有语义、不放宽任何断言。**

## 1. 目标与范围

目录与容量这套机制**已经能用**：目录可以跨多个块增长、磁盘满与 inode 耗尽都有既有用例。但它现在是**隐含行为**——上限是多少、到了上限报什么错、失败后留下什么状态，都要从代码里推。

本批次的目标是把这些变成**有测试、有文档、可复现**的显式契约，并修掉其中确实会 panic 的一处。范围限定在：

- 目录项的数量边界（跨块 → 跨间接块 → `MAXFILE` 上限）
- 三类容量耗尽的失败语义与失败后的状态（inode 耗尽、块耗尽、目录达上限）
- 名字长度边界的**别名效应**（已有用例钉住行为，本批次把后果写清楚并显式断言）

**不做**：VFS / 挂载 / `/proc` 伪文件系统（那是本方向的后续子项，需要新抽象）、`NINODES` / `FSSIZE` 的调整、磁盘格式变更、POSIX 目录接口（`readdir`）。

## 2. 现况调研（逐条对当前代码，基线 `5da427b7`）

### 2.1 数据结构的硬数字

| 项 | 值 | 出处 |
| --- | --- | --- |
| 目录项大小 | **16 字节**（`ushort inum` + `char name[14]`） | `kernel/fs.h` `struct dirent`；`mkfs` 有 `assert((BSIZE % sizeof(struct dirent)) == 0)`（`mkfs/mkfs.c:104`） |
| 每块目录项数 | **64**（1024 / 16） | 推导 |
| 名字上限 | **`DIRSIZ = 14`**，无 NUL 保证（见 2.3） | `kernel/fs.h` |
| 直接块 | **`NDIRECT = 10`** → 前 640 项 | `kernel/fs.h` |
| 间接块 | 1 个，`NINDIRECT = 256` 个块指针 → 第 **641** 项起走间接块 | `kernel/fs.c` `bmap()` |
| 单文件上限 | **`MAXFILE = 266` 块 = 272,384 字节** | `kernel/fs.h`；`kernel/fs.c:669` 在 `writei()` 里拒绝 `off + n > MAXFILE * BSIZE` |
| **目录项数上限** | **17,024 项**（272,384 / 16） | 推导；超界时 `writei` 返回 -1，`bmap` 的 `panic("bmap: out of range")` 不会触发（先被 `writei` 挡住） |
| 磁盘 inode 上限 | **200**（`NINODES`） | `mkfs/mkfs.c:24`；`ninodeblocks = 200 / IPB + 1 = 13`（`:43`），写进 `sb.ninodes`（`:117`） |
| 数据区 | 3,153 块（`FSSIZE 3200` − 元数据 47） | `kernel/param.h` |

**关键推论：目录项上限是可达的。** 目录项可以指向同一个 inode（硬链接），所以一个 inode 就能支撑上万条目——`usertests` 的 `bigdir` 用的正是这个办法。17,024 项只占 266 块，远小于 3,153 块的数据区，所以**先到瓶颈的是目录自身的 `MAXFILE`，不是磁盘**。

### 2.2 目录在磁盘上就是一个普通文件

`dirlink()` 在目录末尾追加 16 字节（或复用 `inum == 0` 的空洞），走的是 `writei()` → `bmap()` 这条与普通文件相同的路径。因此目录的容量、多块增长、间接块都**复用**文件的那套机制，没有独立实现。

- `dirlookup()`（`kernel/fs.c:710`）线性扫描整个目录，每项一次 `readi()`；读不回来时 **`panic`**。
- `dirlink()`（`:745` 起）：先查重名 → 找空洞 → 追加；`writei` 失败返回 **-1**。
- `create()`（`kernel/sysfile.c:308` 起）在 `dirlink` 失败时跳 `fail:`，**回收刚分配的 inode**（`nlink = 0` → `iupdate` → `iunlockput`），返回 0；`open(O_CREATE)` 因此得到 -1。

### 2.3 名字长度：截断而不是报错

`skipelem()`（`kernel/fs.c:781`）在提取路径元素时：`len >= DIRSIZ` 就 `memmove(name, s, DIRSIZ)`——**截断成 14 字节且不写 NUL**。

`usertests` 的 `fourteen` 已经把这条钉成了契约：

- `mkdir("123456789012345")`（15 字符）**必须成功**；
- 之后用 14 字符的 `"12345678901234"` 能打开它；
- 对已经因截断而存在的名字再 `mkdir` 必须失败。

⇒ **本批次不改这个语义**，改它会直接破坏既有断言。要做的只是把"15 字符以上的不同名字会在 14 字符处互相别名"这一后果写进文档并显式断言。

### 2.4 现有覆盖（`usertests` 共 74 项，与本方向相关的）

| 用例 | 覆盖到什么 |
| --- | --- |
| `fourteen` | 名字截断语义（见 2.3） |
| `bigdir` | 单目录 **500** 项（= 8 块），经硬链接；创建与删除 |
| `diskfull` | 反复写 `MAXFILE` 大小的文件直到写失败，再验证此时目录操作的行为 |
| `outofinodes` | 持续创建直到 `open` 失败（约 200 个），再全部删除 |
| `bigfile` / `bigwrite` / `writebig` | 大文件读写；`writebig` 打到 `MAXFILE` 上限 |
| `linkoverflow` | `nlink` 达到 `NLINK_MAX`（32767）后的拒绝 |
| `createdelete` / `concreate` / `linktest` / `linkunlink` / `dirfile` / `subdir` / `rmdot` / `unlinkcwd` | 一般目录与链接语义 |
| `manywrites` / `partial_write` / `badwrite` / `truncate1-3` | 写入的部分失败与截断 |

**已经很好**：一般目录语义、磁盘满、inode 耗尽、大文件上限都有覆盖。

## 3. 缺口

| 编号 | 缺口 | 证据 |
| --- | --- | --- |
| **G1** | 目录的**间接块路径与 `MAXFILE` 上限从没被测过**。`bigdir` 停在 500 项（8 块），而间接块从第 641 项才开始，上限是 17,024 项 | `bigdir` 源码 `enum { N = 500 }` |
| **G2** | 目录读不回来时 **`panic` 而不是返回错误**，有四个调用点：`dirlink`（`fs.c:745`）、`namex`（`:886`）、`sys_unlink`（`sysfile.c:252`）、`create`（`:308`）。一次坏数据 = 内核 panic | `panic("dirlookup read")` / `panic("dirlink read")` |
| **G3** | **失败语义不可区分且未文档化**：inode 耗尽、块耗尽、目录达上限、无写权限，用户态一律只看 `-1`（xv6 没有 errno）。失败后"目录是否仍一致、有没有留下半截目录项或漏掉的 inode"没有任何断言 | `create()` 的 `fail:` 只回收 inode |
| **G4** | 名字截断的**别名后果**没有显式断言（`fourteen` 只覆盖创建与可达，没有覆盖"两个 15 字符名字互相别名"） | `skipelem` `:794-795` |
| **G5** | `NINODES = 200` 偏小。（`outofinodes` 在 ~200 就失败。）但调大它会移动 `inodestart` / `bmapstart`，**属于磁盘布局变更**，需要 `FSMAGIC` 处理与旧镜像拒绝——**本批次不做** | `mkfs/mkfs.c:24` / `:43` |

## 4. 冻结的接口与语义（本批次不动）

1. **磁盘格式不变**：`FSMAGIC`、`dinode`（64 字节）、`dirent`（16 字节）、`DIRSIZ`（14）、`NDIRECT`（10）全部保持。
2. **名字截断语义不变**（见 2.3），只补文档与断言。
3. **不改 `user/usertests.c`，不放宽既有断言**（上游 `AGENTS.md` 与路线图 §7 都写死）。
4. **不调 `FSSIZE` / `NINODES`**：前者调了也不是本子项的内容（上游明确"不能只调大 `FSSIZE`"），后者是布局变更。
5. **不改系统调用 ABI**：`create`/`dirlink` 的 -1 语义保持，不做 errno。G3 靠"文档 + 失败后状态断言"解决，不靠新增返回值。

## 5. 分批计划

### 13.1 事实化与自检（本批次主体）

新增 `user/fslimit.c`，接入 `Makefile` 的 `UPROGS`、`user/help.c` 的命令索引、`test-xv6.py` 的 `DEDICATED`（进单核/三核 CI）。断言分六组：

1. **跨块**：单目录 700 项——跨过 10 块边界（第 641 项起走间接块）。逐项确认可查找、可 `stat`。
2. **上限**：目录增长到 `MAXFILE` 项上限（17,024）时，下一次创建**干净失败**；此后**目录仍可读**（既有条目仍在、名字仍可解析）、**仍可删**（删除后能再次创建）。
3. **inode 耗尽**：持续创建直到 `open` 失败；确认失败是干净的（没有半截目录项），全部删除后**可以重新创建**（inode 被回收）。
4. **块耗尽**：填充数据块直到写失败；确认目录写入失败后目录仍一致。
5. **名字边界**：14 / 15 / 128 字符（`MAXPATH`）三处的行为；**显式断言别名**——两个仅在第 15 个字符处不同的名字会指向同一个目录项。
6. **失败后的一致性**：每一组之后用既有会计口径核对——`df` 的块数、`free` 的空闲页、以及"重新挂载（重启）后目录内容不变"。

**规模与耗时**：先测创建速率，再定第 2 组的做法。17,024 次硬链接如果在 QEMU 里超出专用用例默认 120 秒超时，就把它**拆成独立用例并显式放宽 `--timeout`**（`README.md` 已写明 `--timeout` 可调），不要为了塞进默认超时而缩小到测不到上限。

### 13.2 硬化：目录不可读时返回错误而不是 panic（可选，需先确认收益）

把 `dirlookup` / `dirlink` 的 `panic` 改成可传播的错误，并让四个调用点各自处理（`namex` 返回 0 / `create` 走 `fail:` / `sys_unlink` 返回 -1 / `dirlink` 返回 -1）。

**诚实的前提**：用户态构造不出"大小不是 16 倍数、或有空洞读不回来"的目录，所以这一项**在客户机里无法写负向用例**——除非在宿主侧用 `mkfs` 造一个坏镜像（`test-harness.py` 已在做宿主侧的错误注入，可以扩展）。因此：

- 若扩展宿主坏镜像注入可行 ⇒ 做成有负向用例的硬化；
- 若不可行 ⇒ **只做代码审查与文档**，明确写成"已识别但未验证"的限制，不声称修好。

不做"改为 panic 以外但同样不可测"的改动。
