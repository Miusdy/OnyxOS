## 1. 目标与范围

HachileiOS 已具备教学型操作系统的核心基础功能：启动与中断、进程管理、抢占式调度、虚拟内存、文件系统、设备 I/O、管道和 Shell。它能够独立运行用户程序、管理资源并持久保存文件。

后续目标是先建立覆盖已有功能的持续验证，再补充交互控制和权限体系，最后按学习方向扩展内存、存储或网络。目标不是一次性实现 Linux，也不以 GUI、命令数量或展示效果作为完整性的标准。

每个实施批次必须明确：用户可观察的行为、系统调用语义、资源生命周期、并发规则、错误处理和验收测试。

## 3. 阶段一：补齐自动化验证（最高优先级）

目标：使现有能力的退化能够被 CI 稳定发现，作为后续功能的验收基础。

- [x] 为专用用户测试添加独立的宿主执行入口，支持超时、失败诊断和运行结果汇总。
- [x] 自动运行 `cowtest`、`kmemtest`、`waitxtest`、`cputest`、`priotest`。
- [x] 在 Linux CI 中增加 `CPUS=1` 和 `CPUS=3` 验证，按测试适用条件分配用例。
- [x] 增加多核 fork/exit/wait、管道读写、COW 写入、文件创建/删除的组合压力测试。
- [x] 保存失败时的串口输出、具体命令、CPU 配置与提交信息；设置任务级超时。
- [x] 核对 README 的功能声明、命令清单、运行限制和测试入口。

重点约束：当前 `priotest` 仅让两个子进程竞争，并比较高低优先级进程的 CPU 时间。在多核空闲情况下，两者可能同时运行，不能直接要求高优先级进程获得更多时间。先在单核验证竞争与老化，再设计工作进程数超过核心数的多核测试。统计测试也应使用合理误差范围，不能依赖主机固定运行速度。

主要改动位置：`.github/workflows/test.yml`、`test-xv6.py`、`test-harness.py`、各专用测试程序。

验收标准：

1. 所有适用用例在单核、多核配置下通过；开发阶段每种配置至少连续验证 10 次，不以自动重试掩盖失败。
2. 人为使某个测试返回失败或挂起时，CI 必须失败并保留可定位的日志。
3. 完整 `usertests` 和崩溃恢复测试继续通过；测试进程退出后不遗留 QEMU。

## 4. 阶段二：信号与终端作业控制

目标：用户可以中断前台程序、管理后台任务，Shell 在子进程异常退出后仍可继续工作。

- [x] 设计并实现最小信号语义：待处理位、默认终止/停止/继续动作、用户处理器、屏蔽位及 `sigreturn`。
- [x] 定义信号在 fork/exec/exit、睡眠和系统调用期间的行为；原有 `kill(pid)` 保持“请求退出”兼容，新增 `signal(pid, sig)`。
- [x] 实现进程组、终端前台进程组和组信号；fork 继承进程组，因此管道进程共享作业归属。
- [x] 实现 Ctrl-C 对前台进程组投递 SIGINT；被中断的控制台读返回 `-1` 并丢弃未提交输入行。
- [x] 实现停止/继续状态、`waitpg` 状态报告，以及 Shell 内建 `jobs`、`fg PGID`、`bg PGID`。
- [x] `top` 默认持续刷新并可由 Ctrl-C 终止，同时保留显式轮数的有限运行模式。

接口约定：信号编号为 `SIGTERM=1`、`SIGINT=2`、`SIGKILL=3`、`SIGSTOP=4`、`SIGTSTP=5`、`SIGCONT=6`。`SIGKILL`、`SIGSTOP` 不可屏蔽或捕获；`SIGCONT` 不可屏蔽但可以捕获。处理器需显式调用 `sigreturn()` 恢复被中断寄存器。`SIG_DFL` 与 `SIG_IGN` 分别用 `(void (*)(int))-1` 和 `(void (*)(int))-2` 表示，避免合法用户代码地址 0 与默认动作冲突。用户处理器运行期间暂时屏蔽可屏蔽信号，返回时恢复原屏蔽位。`SIGINT` 默认终止整个前台作业组；`SIGTSTP` 默认停止，`SIGCONT` 恢复停止组。被信号打断的控制台读取返回 `-1`，不会自动重启。

作业控制当前是小型 Shell 接口：命令独立成组，管道成员继承组；`jobs` 显示组号，`fg PGID` 前台恢复、`bg PGID` 后台恢复。作业表容量为 16，命令需要显式提供 PGID；尚未实现 POSIX `sigaction` 结构、信号队列、登录会话、TTY 驱动行规程或后台终端读的 SIGTTIN 规则。

主要改动位置：`kernel/proc.h`、`kernel/proc.c`、`kernel/trap.c`、`kernel/console.c`、系统调用接口、`user/sh.c`、`user/sigtest.c`。

验收标准：Ctrl-C 能终止前台命令和前台管道，不误杀 Shell 或后台任务；停止/恢复行为可重复验证；阻塞进程能被正确唤醒；处理器返回后寄存器与用户栈正确恢复；子进程均可回收，无僵尸或资源泄漏。

## 5. 阶段三：用户身份与权限体系

目标：从所有进程共享同等权限的环境，发展为具有最小访问控制的系统。

- [x] 明确最小身份模型：UID/GID、特权身份，以及 fork/exec 的继承规则；复杂身份切换另行设计。
- [x] 为 inode 增加所有者和访问权限，并实现文件读写、目录搜索和目录修改权限检查。
- [x] 约束 `kill`、信号投递、`setprio`、设备节点创建等操作，防止任意进程控制其他身份的资源。
- [x] 增加最小账户管理与登录流程；认证设计需包含密码存储和失败处理，不能仅通过输入用户名切换身份。
- [x] 明确磁盘格式变更策略，更新 `mkfs`，对旧镜像提供明确拒绝或迁移路径。
- [x] 在保持现有统计工具可用的同时，定义跨用户查看进程和内核日志的权限边界。

实现边界：UID 0 为特权身份，fork 继承、exec 保留 UID/GID；只有实际 UID 和一个主组，无 saved-uid、setuid 位或补充组。文件权限按 owner/group/other 选唯一一档，已打开的文件描述符不因之后降权或 chmod 被撤销。进程控制仅同 UID 或 root；组信号只投递给有权限的成员，全部无权限返回 -1。设备节点创建、内核日志和密码回显控制仅 root；进程身份与统计对所有用户公开。

账户流程：init 启动 login，始终通过口令认证后进入 Shell。固定预置 root、alice、bob 三账户（初始口令同用户名，仅供教学），root 用 `passwd NAME` 改密。账户文件是 root:0600 的固定长度二进制数据库；PBKDF2-HMAC-SHA256、10,000 轮、每账户 16 字节随机盐；错误认证等待 1/2/4/8 秒，缺失或损坏账户拒绝登录。口令不回显，空值/超长/确认不一致均拒绝。哈希工作因子、固定账户和缺少完整会话隔离是明确的教学限制。

磁盘策略：`FSMAGIC=0x10203041`，旧 `0x10203040` 明确报旧 inode 格式并要求重建；不自动迁移。早期同格式但缺少账户文件的镜像同样拒绝登录，需备份数据后重建。`mkfs` 建立账户与私有主目录；改密原位以一次日志事务更新，不截断数据库。镜像扩至 3200 块，仍为单块位图，日志和缓存大小不变，已通过磁盘满及崩溃恢复测试。

主要改动位置：`kernel/proc.h`、`kernel/fs.h`、`kernel/stat.h`、`kernel/sysfile.c`、`kernel/sysproc.c`、`mkfs/mkfs.c`、`common/auth.c`、`user/login.c`、`user/passwd.c`、`user/privtest.c`、`test-auth.py`、`test-stage3.py`。

验收标准：至少两个不同身份的进程不能越权读写文件、修改目录、终止或调优对方进程；权限可持久保存；fork/exec 后身份正确；失败路径无引用计数或锁泄漏；特权操作有明确测试。原有回归在明确的测试身份下继续通过。

验收结果：单核/三核专用集合、完整 `usertests`、三项崩溃恢复、登录/改密/重启持久性均通过；跨身份权限自检在每种配置连续通过 10 轮。宿主测试 21 项和 18 组 PBKDF2 参考向量通过。详见 [阶段三验证记录](stage3-validation.md)。

## 6. 阶段四：按学习方向扩展

下列能力属于后续候选，不要求全部完成后才能称为教学操作系统。完成阶段一后，可根据目标选择一条方向；每个子项单独设计和验收。

| 方向 | 建议顺序与范围 | 关键依赖及验收 |
| --- | --- | --- |
| 虚拟内存（本批选择） | 匿名 mmap/munmap → 文件私有映射 → 映射页按需加载，已实现 | 单核/三核各 10 轮专项及完整回归通过；接口见[阶段四验证记录](stage4-validation.md) |
| 文件系统 | 扩展容量与目录能力 → VFS/挂载 → `/proc` 等伪文件系统 | 先明确磁盘格式与接口边界；验证大文件、磁盘满、挂载路径和崩溃恢复，不能只增加 `FSSIZE` |
| 网络 | QEMU 网卡驱动 → ARP/IPv4/ICMP → UDP/socket → TCP | 验证收发、边界检查、超时、丢包及资源回收；TCP 作为独立的大批次 |
| 用户线程 | 共享地址空间线程 → 线程退出/等待 → 用户同步原语 | 先重新审查 COW 和页表代码的单线程假设、并发解除映射及多核 TLB 同步；以压力测试验证 |
| 内存压力 | 内存不足错误路径 → 页面回收设计 → 可选 swap | 必须先具备回收策略、页面状态和可控压力测试；不把 swap 当作近期必需功能 |

- [x] 匿名 `mmap`/`munmap`、只读/读写权限、区域管理与部分解除映射。
- [x] 普通文件私有映射、独立文件引用和按页读取。
- [x] 匿名/文件页按需加载、fork COW、exec/exit 回收、失败回滚及单核/多核验收。

本批范围与接口：`mmap`/`munmap`（系统调用 47/48），支持只读/读写的匿名与普通文件私有映射。映射区域位于 1–2 GiB，必须位于现有堆之后，`sbrk` 不得与现存映射重叠；每进程最多 16 个区域、单次最多 64 MiB。匿名页首次访问清零，文件页首次访问读取；私有修改不写回。关闭 fd/unlink 后映射引用有效；fork 的驻留可写页使用 COW，未驻留页独立加载，exec 成功与 exit 释放全部映射。解除映射支持首尾裁剪和中间拆分，槽不足时不修改原映射。

本批明确不包含 `MAP_SHARED`、写回、可执行映射、`mprotect`、固定地址、ELF 按需执行、页面回收或 swap。文件变化与 EOF、锁和 I/O、资源上限及错误语义见[阶段四验证记录](stage4-validation.md)。其余四条方向保持候选状态，不同时重写多个子系统。

验收入口：`mmaptest` 已纳入单核/三核 `dedicated` 与 Linux CI；覆盖 COW、保护/越界访问、解除映射、文件偏移/EOF、冷映射系统调用缓冲区、映射表满时的失败回滚、并发与 OOM 后资源回收。最终本地结果见阶段四验证记录。

## 7. 实施与交付规则

1. 推荐主线为：自动化验证 → 信号与作业控制 → 身份与权限。可选扩展按目标另行选择，不同时大规模重写多个子系统。
2. 每批先写清接口、并发不变式和错误语义，再实现功能与测试。接口和实现必须在同一批次内保持可用。
3. 变更共享结构体、系统调用或磁盘格式时，同时更新用户程序、镜像生成工具和兼容性说明。
4. 每批完成后执行适用专用测试、完整 `usertests` 和崩溃恢复测试；并发相关改动必须覆盖单核与多核。
5. 提交说明应包含问题、行为变化、测试结果和仍有限制；通过验收后才能将本文对应事项标为完成。
6. 不承诺未经验证的实时性、安全隔离强度、POSIX 兼容性或真实硬件支持。
